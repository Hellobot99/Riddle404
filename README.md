# Riddle404 · 지워진 밤을 재생하라

사건이 난 밤의 기록이 삭제된 도시. 같은 밤을 일곱 번 재생하며 관측자를 배치해, 사건 현장에 있던 단 한 사람을 찾는 1~6인 협동 추리 웹게임입니다.

## 규칙

- 지도는 **장소 6곳 × 시간대 8칸**입니다. 첫 번째 장소는 사건 현장이고, 기록이 지워져서(404) 관측할 수 없습니다.
- **범행 시각에 현장에 있던 사람은 범인 한 명뿐**입니다.
- 루프마다 칸에 관측자를 놓으면, 재생이 끝난 뒤 그 칸에 누가 있었는지와 남은 기록이 모두에게 공개됩니다.
- 추정 시간대 안의 **두 시각**에 현장 쪽 소리 기록이 남아 있습니다. 하나는 범행 시각이고, 하나는 범행과 무관한 소리입니다. 문장으로는 구별되지 않습니다.
- 가짜 소리가 난 시각에는 현장에 아무도 없었으므로, 그 시각에는 다섯 명이 모두 다른 방에서 보입니다. 진짜 범행 시각에는 한 명만 끝까지 보이지 않고, 그 사람이 범인입니다.
- 현장에 있던 사람은 누구든 기록에 남지 않습니다. 범인도 범행 전후 현장에 머물면 그 시각엔 안 보이고, 범인이 아닌 사람도 밤중에 현장에 들를 수 있습니다. 안 보인다고 범인은 아니지만, 그 시각의 방을 모두 봤는데 없다면 현장에 있었던 것입니다.
- 수사 화면의 **노트** 탭이 소리가 난 시각과 그 시각의 알리바이를 자동으로 정리해 줍니다. 결론은 플레이어가 내립니다.
- **범행 수단과 동기**도 맞히면 보너스입니다. 용의자들의 수상한 기록에는 물건이 하나씩 나오는데, 범인이 범행 30분 전후에 다루던 물건이 진짜 수단입니다. 진짜 동기의 핵심어가 담긴 기록(쪽지, 서류 등)도 범인이 있던 다른 시각의 방에 숨어 있습니다. 고발할 때 범인과 함께 고르고, 맞히면 각각 +30점입니다.
- 고발은 루프 중 언제든 투표로 할 수 있고, 기회는 한 번뿐입니다. 일찍 맞힐수록 점수가 높습니다. 마지막(일곱 번째) 재생이 끝나면 반드시 고발해야 합니다.

### 난이도

방장이 대기실에서 1~5단계를 고릅니다. 단계가 오를 때마다 변형 규칙이 하나씩 쌓이고, 해결하면 단계마다 +40점입니다.

| 단계 | 더해지는 규칙 |
| --- | --- |
| 1 기본 | 없음 |
| 2 공범 | 범인의 위조 기록에 공범이 함께 찍혀 거짓 증언을 합니다. 함께 찍혔다고 증인이 되는 건 아닙니다 |
| 3 정전 | 한 시각 동안 기록에 사람 수만 남습니다 (브리핑에서 공개) |
| 4 잠긴 문 | 한 통로가 몇 시간 잠겨 있습니다 (브리핑에서 공개). 범인의 허점은 바로 그 잠긴 문입니다 |
| 5 이중 위조 | 범인이 범행 시각과 바로 옆 시각까지 두 칸을 위조해, 허점이 한 칸 더 바깥에 있습니다 |

어떤 단계, 어떤 조합에서도 허점은 범인에게만 생기고, 정전이 허점을 다 가리지 않도록 서버가 검증한 사건만 나옵니다.

### 인원 보정

탐정 팀 전체 관측 수를 고정해서, 사람이 적어도 불리하지 않게 했습니다.

| 인원 | 구성 | 탐정 팀 관측 / 루프 |
| --- | --- | --- |
| 1~3 | 탐정만 | 4 (남는 몫은 루프마다 돌아가며 받음) |
| 4 | 탐정 3 + 교수 1 | 4 |
| 5~6 | 탐정 + 교수 1 | 5 |

### 교수 (4인 이상)

요원 중 한 명이 몰래 교수(방해자)가 됩니다. 교수는 진범과 그날 밤의 진실을 알고 시작합니다.

- 탐정인 척 관측자를 1개 놓습니다.
- **기록 변조**: 자기가 관측한 칸의 결과를 가짜로 공개합니다. 4인 판은 1회, 5~6인 판은 2회 쓸 수 있습니다.
- **노이즈**: 한 칸을 그 루프 동안 관측할 수 없게 만듭니다. 1회 쓸 수 있습니다.
- 같은 칸은 몇 번을 다시 봐도 결과가 같아야 합니다. 그래서 다시 관측하면 변조가 드러나고, 한 사람이 같은 시각 두 곳에서 보이면 화면에 빨갛게 표시됩니다.
- 탐정이 범인을 맞히면 교수 지목 투표가 이어집니다. 교수까지 잡으면 완전 해결입니다.

## 무대와 이름

수사 화면의 기본 보기는 **지도 + 재생 타임라인**입니다. 타임라인에서 시각을 고르면 지도에 그 시각의 관측 결과가 뜨고, 방을 눌러 관측자를 놓습니다.

무대와 인물 이름은 서버가 준비된 데이터에서 무작위로 뽑아 조합하고, AI는 이야기와 문장만 씁니다.

- **방 구조** `data/layouts.json`, **테마와 방 이름** `data/themes.json`, **이름** `data/names.json`. 구조와 테마를 짝짓고 현장 위치도 무작위로 정해서, 같은 조합이어도 매번 다른 무대가 나옵니다. 형식은 [data/README.md](data/README.md)에 있습니다.
- 배경 이미지가 있는 고정 지도는 `maps/`에 직접 만들 수 있습니다. [maps/README.md](maps/README.md)

## 배경음악

`public/audio/`의 음원을 진행 단계에 맞춰 바꿔 틉니다([public/music.js](public/music.js)). 곡이 바뀔 때는 서서히 겹쳐 넘어가고, 화면 왼쪽 아래 버튼으로 끌 수 있습니다.

| 단계 | 곡 | 효과음 |
| --- | --- | --- |
| 로비·대기실 | lobby | |
| 브리핑 | briefing | |
| 수사 | investigate (남은 재생 3번 이하면 investigate-late) | 재생 결과가 공개될 때 replay_start, 정전 기록이 섞이면 power_down |
| 고발 투표 | vote | |
| 결과 | 해결이면 reveal, 실패면 fail | 결과 화면에 들어설 때 result |

원본은 WAV(`*.wav`, 저장소에 올리지 않음)이고, 웹에서는 AAC로 압축한 `.m4a`를 씁니다. 원본을 바꿨다면 다시 압축하세요.

```bash
cd public/audio && for f in *.wav; do afconvert -f m4af -d aac -b 160000 "$f" "${f%.wav}.m4a"; done
```

## AI는 어디에 쓰나

**AI는 사건을 만들 때 한 번만 부릅니다.** 사건은 미리 몇 개 만들어 두므로, 게임 중이나 결과 화면에서는 AI를 부르지 않습니다.

- 누가 언제 어디 있었는지는 **서버가 무작위로 만들고 검증**합니다. 무대(테마, 방 이름)와 인물 이름도 서버가 데이터에서 뽑습니다.
- AI는 그 구조에 제목, 인물 설정, 기록 문장, 그리고 게임이 끝나고 공개할 **사건의 전말**을 한 번에 씁니다. 그래서 어떤 문장이 나와도 사건은 항상 풀립니다.
- 결과 화면의 수사 기록, 교수 행적, 요원 평가는 서버가 관측·투표 기록으로 바로 정리합니다. 결과 화면에서는 그날 밤의 진짜 동선을 지도 위에 다시 재생하고, 범행 시각에 위조된 기록을 드러냅니다.
- AI 호출이 실패하면 기본 문장으로 대신하므로, 게임은 끊기지 않습니다.

## 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env   # 그다음 .env에 GEMINI_API_KEY 입력
npm start              # http://localhost:3000
```

- API 키는 [Google AI Studio](https://aistudio.google.com/apikey)에서 발급받습니다.
- **키는 `.env`에만 넣습니다.** `.env`는 `.gitignore`에 들어 있어 커밋되지 않고, 저장소에는 값이 빈 `.env.example`만 올라갑니다.
- `GEMINI_API_KEY`를 비워 두면 테스트 모드로 실행됩니다.
- 혼자 테스트할 때는 같은 브라우저에서 탭을 여러 개 열고, 한 탭에서 만든 방의 초대 링크를 다른 탭에 붙여 넣으세요.
- `npm run check`로 사건 생성기와 게임 규칙을 서버 없이 점검할 수 있습니다.

## 배포 (Render)

저장소에 [render.yaml](render.yaml)이 있어서 Render Blueprint로 바로 배포할 수 있습니다. 싱가포르 지역, 무료 플랜입니다.

1. [Render](https://render.com)에 GitHub 계정으로 가입
2. 대시보드에서 **New → Blueprint** → 이 저장소 선택
3. `GEMINI_API_KEY` 값을 입력하고 **Apply**
4. 배포가 끝나면 `https://<서비스 이름>.onrender.com` 주소로 누구나 접속

잠들지 않게 하기:
- 무료 플랜은 15분간 요청이 없으면 잠들고, 다음 접속 때 깨어나는 데 1분 가까이 걸립니다.
- `KEEP_AWAKE=1`(render.yaml에 들어 있음)이면 서버가 10분마다 자기 `/healthz`를 불러 깨어 있습니다.
- 재시작 등으로 한 번 잠들면 스스로는 못 깨어나므로, [cron-job.org](https://cron-job.org)나 UptimeRobot 같은 무료 모니터링에 `https://<주소>/healthz`를 10분 간격으로 등록해 두면 확실합니다.
- 무료 750시간/월은 **계정 전체 합계**입니다. 다른 무료 서비스까지 깨워 두면 시간이 모자라 월말에 모두 멈춥니다.

주의:
- 방과 사건은 서버 메모리에 있어서, 다시 배포하거나 재시작하면 진행 중인 방은 사라집니다. 인스턴스는 1대로 유지해야 합니다.
- `main`에 푸시하면 자동으로 다시 배포됩니다.

## 환경 변수

`.env.example`에 모두 설명이 있습니다.

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `GEMINI_API_KEY` | (없음) | Gemini API 키 |
| `GEMINI_MODEL` | `gemini-flash-latest` | 사건 문장 생성 모델. 실패하면 `gemini-flash-lite-latest`로 대체 |
| `PORT` | `3000` | 서버 포트 |
| `BRIEF_SECONDS` | `60` | 브리핑 시간(초) |
| `PLAN_SECONDS` | `90` | 루프마다 배치 시간(초) |
| `VOTE_SECONDS` | `30` | 투표 시간(초) |
| `LOOPS` | `7` | 재생 횟수 |
| `CASE_POOL` | `3` | 미리 만들어 두는 사건 수 |
| `MAX_ROOMS` | `200` | 동시에 열 수 있는 방 수 |
| `CREATE_LIMIT` | `5` | IP당 10분에 만들 수 있는 방 수 |
| `TRUST_PROXY` | (꺼짐) | 리버스 프록시 뒤에서 실제 IP를 쓰려면 `1` |
| `KEEP_AWAKE` | (꺼짐) | `1`이면 10분마다 자기 주소(`RENDER_EXTERNAL_URL`)의 `/healthz`를 불러 잠들지 않게 함 |

## 구조

```
server.js           방 관리, 단계 진행, 타이머 (Express + Socket.IO)
src/puzzle.js       사건 구조 생성과 검증 (누가 언제 어디, 범행 시각, 기록 위치)
src/game.js         게임 규칙: 관측 배치, 변조·노이즈, 재생, 투표, 판정
src/cases.js        사건 풀: 무대와 이름을 뽑고, 서버가 구조를 만들고, AI가 문장을 입혀 미리 쌓아 둠
src/maps.js         무대 만들기: 방 구조 × 테마 조합, 고정 지도 읽기, 통로 계산
data/               사건 재료: 방 구조, 테마, 이름 (data/README.md)
maps/               직접 그린 고정 지도 (maps/README.md)
public/maps/        고정 지도의 배경 이미지 (선택)
src/ai.js           Gemini 호출: 사건 문장과 전말 (사건을 만들 때만)
src/report.js       결과 리포트: 결정적 관측, 교수 행적, 요원 평가 (AI 없이)
public/             화면 (HTML/CSS/JS), music.js: 배경음악과 효과음, audio/: 음원
scripts/            규칙 점검(check-puzzle.js), 방 구조 자동 생성(gen-layouts.js)
```
